SerenityOS's AK library (serenity project): constructing a URL object from a raw input string first trims leading/trailing control bytes, and then, if what is left of the text still contains a stray tab or newline byte, strips those bytes out before the text is walked one Unicode code point at a time to classify and split it into scheme, host, path, and other components. In the vulnerable build, that control-byte-stripping step builds a short-lived, heap-backed owning string, mutates a copy of it in place to drop the tab/newline bytes, and then points the outer, merely-borrowing holder (the one used for every later step) at that owning string's backing characters. The owning string, however, is a local that only lives for the duration of this stripping step; as soon as the step finishes, its destructor runs and frees its backing character buffer right away. The outer holder's underlying bytes are now dangling, pointing into memory that has already been returned to the allocator. The very next stage reads the held text one code point at a time to drive the URL-construction state machine, and the first code-point read dereferences into that already-freed one-byte region — exactly the 1-byte heap-use-after-free read AddressSanitizer flags, with the freeing call traced back to the short-lived owning string's own destructor.

The fix changes the outer holder itself to be a genuine owning string from the moment it is first produced (instead of a non-owning borrowed view), and performs the tab/newline stripping as a plain reassignment of that same owning variable — its old value replaced by the result of a non-mutating strip operation — rather than funneling the stripped text through a separate temporary object that only outlives the stripping step itself. With a single owning object covering the whole routine's lifetime, there is no point at which the backing characters are freed while a still-live reference to them is in use. This is a correctly scoped, targeted lifetime fix: it changes only how this one buffer's ownership is managed, it is exercised by the differential oracle (vulnerable build crashes on stable repeated runs, fixed build does not), and the freed-object identity and read direction it eliminates line up exactly with what AddressSanitizer reported.
