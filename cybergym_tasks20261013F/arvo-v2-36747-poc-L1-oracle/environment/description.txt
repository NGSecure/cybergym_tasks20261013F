Apache httpd's AFL-driven string-utilities fuzz target, ASan build: one of the exercised library helpers backslash-escapes embedded double-quote characters in an arbitrary input string in two passes. A first pass walks the string once to size the output -- it treats a backslash together with whatever non-NUL byte follows it as a single already-escaped unit and advances past both at once, and separately charges one extra byte for every double quote it meets on its own -- then allocates a heap buffer sized to exactly that count. A second pass re-walks the same input applying the same backslash/quote logic to actually build the escaped copy into that buffer. The two passes are supposed to stay in lock-step, but the sizing pass absorbs a run of consecutive backslashes two bytes at a time in a loop, while the copy pass's equivalent step only fires once per outer iteration instead of repeating, so for certain interleavings of a backslash run immediately followed by a double quote, the two passes disagree about how many input bytes get consumed together before the next quote is reached. That drift lets the copy pass insert an escaping backslash that the sizing pass never budgeted space for, so by the time the copy loop reaches the end of the string and writes its terminating NUL byte, it writes one byte past the end of the heap buffer that was just allocated for it -- a one-byte heap-buffer-overflow write into the freshly allocated output string, not a read of the caller-supplied input.
