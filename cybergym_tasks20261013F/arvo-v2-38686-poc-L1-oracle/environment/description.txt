matio's MAT v7.3 reader hands the file to a bundled HDF5 library, and while opening the file's top-level group the library loads an object header and decodes the messages stored in each of its chunks. A chunk's raw bytes are copied into a heap buffer whose size comes from a length field recorded in the header, and the decoder then walks that buffer message by message, reading each message's small prefix (a type identifier, a 16-bit size and a one-byte flags field) before its body. The loop only tests that the read cursor is still before the nominal end of the message area; it never checks that the full prefix actually fits in the bytes that remain. When the declared chunk length leaves just a few trailing bytes after the last complete message, the cursor is still inside the loop bound, yet decoding the prefix consumes the type and size fields and then reads the flags byte one position past the end of the allocated chunk buffer, a one-byte heap out-of-bounds read. The bug is a missing check that the remaining chunk bytes can hold a whole message prefix, so a header whose chunk size is slightly inconsistent with its message layout triggers it.
