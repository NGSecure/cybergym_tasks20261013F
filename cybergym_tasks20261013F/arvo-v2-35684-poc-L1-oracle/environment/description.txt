The Sleuth Kit's FAT filesystem module, exercised while `fls` walks a FAT image's directory tree and recovers orphan/deleted inodes, builds a linked list of data-run descriptors for each file's non-resident attribute by following the file's cluster chain through the FAT. When that chain is corrupted (or adversarially crafted) so that it loops back on itself -- a cluster pointing to one already visited -- the run-list builder detects the cycle mid-construction and frees the partially built run list to avoid returning a self-referential chain, but the local variable that still references that list is left holding the stale pointer instead of being reset to empty. Execution then falls through to the function's normal completion path, which still treats that variable as a valid, non-empty run list and hands it straight to the lower attribute layer that threads data runs onto the file's attribute, so that layer walks and dereferences nodes inside the allocation that was just freed a few lines earlier in the same call. Under a libFuzzer/ASan harness driving FAT inode/directory walking, this surfaces as an 8-byte heap-use-after-free read: the loop-detection cleanup and the subsequent attribute-linking step both operate on the same run-list handle without the first step invalidating it for the second.
