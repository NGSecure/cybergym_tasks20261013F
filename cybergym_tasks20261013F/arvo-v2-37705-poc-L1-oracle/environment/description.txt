Draco's edge-breaker mesh decoder (the libFuzzer mesh-decoding entry point, built with an undefined-behavior sanitizer) rebuilds a mesh's vertex/corner connectivity by replaying a stream of topology events that were valence-predicted while the mesh was being compressed. For each connectivity step the decoder walks into a small per-context buffer of previously stashed symbol values, pulls one entry back out by decrementing a counter into that buffer, and uses the pulled-out value directly as the index into a tiny, fixed-size lookup table that translates a handful of known symbol codes into the actual topology operation to perform next. That pulled-out value is never range-checked against how many entries the lookup table actually holds before it's used as an index — the decoder implicitly trusts that whatever was entropy-decoded into the per-context buffer earlier in the bitstream always falls inside the small handful of legal symbol codes. A corrupted or adversarially crafted bitstream can steer the earlier entropy-decoding step into depositing a symbol value outside that legal range into the per-context buffer; when connectivity decoding later consumes that value as a table index, the lookup reads past the end of the table into adjacent memory, and the bogus "topology" it reads back then drives the rest of connectivity reconstruction. Root cause: the valence-predicted symbol-to-topology translation step indexes a fixed-size lookup table with a value taken straight from attacker-influenced per-context bitstream state, with no check that the value is actually one of the handful of codes the table was built to represent.
