SELinux's CIL compiler (the secilc CIL-build fuzz target) crashes with an AddressSanitizer heap-buffer-overflow read while resolving a policy's "neverallow" assertions during the final binary-policydb-build phase: the pairwise bitmap comparison routine used to intersect two type/attribute bitmaps reads a few bytes immediately before the start of one of the large per-type bitmap buffers that were allocated earlier while converting a type's attribute set into its binary representation. The underflow read is not a defect in the comparison routine itself, which simply assumes the two bitmaps it intersects describe a consistent total number of declared types; the real defect is upstream, in how the CIL parser handles "blockinherit" statements that let one named block copy another block's contents into itself. Before the fix, the parser's defense against runaway or cyclic inheritance (a block that, directly or indirectly through other blocks, ends up inheriting from itself) was only exercised when a coarse heuristic first judged the lexical nesting of blocks to be unusually deep, and even then the check it ran against each individual blockinherit statement only walked that statement's own ancestor chain in the parse tree -- so it could catch a block inheriting from one of its own textual enclosing blocks, but not two or more blocks that reference each other's contents as siblings outside any common nesting, and not a cycle short/shallow enough to dodge the "unusually deep nesting" trigger entirely. An inheritance cycle that slips past both guards makes the block-copy step duplicate block contents far more times than any well-formed policy would, which desynchronizes the running counts of how many types/attributes exist from what the later binary-policydb pass expects: the bitmap built for one attribute ends up sized for a different total type count than the bitmap it is later intersected against while checking neverallow rules, so the intersection routine's index arithmetic walks off the front of the smaller buffer. The fix replaces both the depth heuristic and the ancestor-only check with a single explicit-stack walk performed unconditionally for every blockinherit, which detects a genuine inheritance cycle (a block revisited anywhere during the walk, not just among its own lexical ancestors) as well as an excessive total inheritance count, and rejects the policy outright instead of letting the resulting mismatched bookkeeping reach the binary-build stage.
