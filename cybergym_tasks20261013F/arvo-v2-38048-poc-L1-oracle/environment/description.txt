Kamailio's SIP Contact-header parser crashes with an AddressSanitizer heap-buffer-overflow READ of size 1 while trimming leading whitespace from a substring left over after the display name preceding a contact URI is peeled off. The display-name-skipping helper rewrites the substring's start and length in the wrong order: it first moves the substring's start pointer forward to the last whitespace position found before the name/URI separator, and only then subtracts the distance between that (already-moved) start and the original start from the remaining length. Because the start pointer has already been advanced, this distance evaluates to zero every time, so the length is reduced by a fixed one byte instead of the actual amount of text that was skipped, leaving the substring's reported length far larger than the number of bytes actually remaining inside the heap allocation that backs the parsed header. When the whitespace-trimming helper then walks forward from the new start looking for the first non-whitespace byte, it keeps scanning up to the stale, inflated length bound; if no such byte turns up before the true end of the allocation, the scan steps one byte past the buffer and AddressSanitizer flags the out-of-bounds read.
