A heap buffer overflow occurs when serializing a Finite State Entropy (FSE) normalized-count table into a caller-supplied output buffer. The serializer has a "safe" mode that skips bounds checks when the buffer is believed to be at least a precomputed worst-case header size, and a checked mode otherwise. The worst-case size estimate is too small: it only counts the table bits per symbol and a small constant, ignoring the 4-bit table-size field initially in the bit accumulator, the extra bit that the first symbols can need, and the final two-byte flush of the bit accumulator. For certain count distributions, a buffer whose size is just above the underestimated bound is wrongly treated as large enough, so the unchecked mode is chosen and the writer emits bytes (including the final flush) one byte past the end of the heap allocation. A compression input producing such a symbol distribution makes the compressor write the table header one byte beyond the output buffer.
