espeak-ng's SSML fuzzer (ASan) hits a 1-byte stack-buffer-overflow READ while synthesizing a clause that contains a long run of more than four consecutive digits. When such a digit run is split into comma-separated three-digit groups for speech, the code hands the first group's substring off to the per-word number translator, whose thousands-group-continuation check looks a few bytes before the start of that substring to see whether the token immediately preceding the number was itself a digit or a group separator. Only one leading padding byte was reserved in the small per-clause scratch buffer before that substring, so for the very first digit group this look-behind read lands before the start of the stack buffer, one byte short of the margin the check actually needs.
