h2o's HTTP/3 QPACK header-decompression code, exercised through the HTTP/3 fuzzing entry point, ASan build: when field-line parsing decodes a header entry whose value is encoded as a literal rather than resolved from the static/dynamic indexing tables, the value-decoding helper first inspects the top bit of the next unconsumed byte in the connection's accumulated receive buffer to decide whether that value's bytes are Huffman-compressed, and only afterward calls the variable-length-integer decoder to read the value's length prefix and checks that the declared length does not exceed the bytes actually remaining before the end of the current header block. Because the Huffman-flag check runs before either of those two validations, a crafted QPACK-encoded header block can be exhausted -- i.e. the running decode cursor can have already advanced to exactly the end of the valid input region -- right at the point where this particular entry's value begins, so the flag check dereferences one byte past the end of the heap-allocated input buffer instead of reading a byte that is actually still part of the block. The destination buffer that will eventually hold the decoded header value is sized and filled correctly afterward; the overflow is purely a premature read against the source/input side -- the decoder's own cursor versus the buffer's end, not the destination allocation -- landing one byte beyond a heap region sized for the request's accumulated unparsed bytes, and nothing is written out of bounds.
