Sleuthkit ISO9660 filesystem parser (fls fuzz target, ASan build): while walking the System Use Sharing Protocol (SUSP) extension records attached to an ISO9660 directory entry, the code that extracts a Rock Ridge "alternate name" sub-record computes the name's length by taking the sub-record's own declared length field and subtracting a fixed small header overhead, then hands that computed length straight to a bounded string copy into a fixed-size name buffer. Before doing so it only checks that the declared length does not make the read run past the end of the SUSP data region -- it never checks that the declared length is at least as large as the header it is about to subtract. A crafted ISO image can therefore declare an alternate-name sub-record whose length field is smaller than the header size, making the subtraction produce a negative value; that negative value is then passed as the copy length, and the sanitizer aborts on the invalid (negative) size argument before any real memory corruption happens. The upstream fix adds an explicit lower-bound check on the sub-record's declared length (rejecting it as truncated/malformed) before the subtraction is performed, so an undersized declared length can no longer be turned into a bogus negative copy size.
