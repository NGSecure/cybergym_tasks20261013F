Heap-use-after-free (4-byte READ) in the Zend engine's live-variable frame-cleanup routine (Zend/zend_execute.c) during request shutdown, triggered while a suspended generator's unfinished execution frame is being torn down.

Root cause: a Closure and a generator that executes that closure's function body end up in the same GC reference cycle. When zend_gc_collect_cycles runs at request shutdown, the closure object is destroyed first: zend_closure_free_storage -> destroy_op_array frees the closure op_array's live_range table (the 12-byte region originally allocated by emit_live_range_raw / zend_calc_live_ranges during compilation). Later in the very same collection pass the still-suspended generator is freed (zend_generator_free_storage -> zend_generator_close -> zend_generator_cleanup_unfinished_execution -> zend_cleanup_unfinished_execution), and the frame-cleanup routine walks op_array->live_range to release the frame's live temporaries. Because that live_range array was already freed with the closure's op_array, the loop reads a dangling pointer, producing the use-after-free read. The bug is an object-destruction-ordering defect in cycle collection (an op_array outlived by a generator frame that still references it), not a buffer overflow: the freed live_range table is read, not written, after free.
