wolfMQTT is a lightweight MQTT client library; this report concerns its MQTTv5 property-list parser, which is shared by several incoming control packets (including AUTH) and walks a cursor over the packet's receive buffer, decoding one variable-length property per iteration until a declared property-list length reaches zero. Several property value kinds (notably binary blobs and UTF-8 strings) are prefixed on the wire by an attacker-controlled two-byte length, and the parser consumes that many bytes by advancing the cursor and decrementing its remaining-bytes bookkeeping without first checking the declared length against how many bytes are actually left before the end of the buffer. When a crafted property declares a length larger than the true remaining space, the cursor is pushed past the end of the heap buffer; the next remaining-bytes figure is then computed as an unsigned subtraction between the original buffer length and the now-overshot cursor offset, which wraps around into a huge bogus value instead of going negative. That corrupted value is handed straight to the routine that decodes the following property's variable-byte-integer identifier as its own trusted bound, defeating that routine's internal length check and letting it keep reading and advancing far outside the allocated buffer. AddressSanitizer observes this as a SEGV / wild-address (unknown) read deep inside the recursive property-identifier decode while the client is processing a malformed packet's property section, with the fault address unrelated to any valid heap object.
