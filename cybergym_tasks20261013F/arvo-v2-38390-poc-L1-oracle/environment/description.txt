A memory-safety bug in ICU's collation rule builder: when a tailoring rule string is compiled, the builder caches, for each code point that has context-sensitive (prefix and contraction) mappings, a compiled value that is really an offset into a shared temporary buffer of serialized tries. If that temporary buffer overflows, it is thrown away and rebuilt, but cached offsets (and per-entry default values left over from an earlier build of the same list) are not reliably invalidated. A later lookup then reuses a stale offset as if it were still valid, so the trie reader starts at a bogus position inside the rebuilt data and reads out of bounds, crashing with a wild-address read. A rule string that creates many prefix-plus-contraction mappings for the same code points, so the buffer overflows mid-build and stale entries are consulted afterwards, triggers it.
