A crafted PHP script triggers a heap use-after-free read in the Zend engine's by-reference foreach over an ArrayIterator subclass. When foreach iterates such an object by reference, the engine first asks the SPL array iterator for a pointer to the current element, which points directly into the iterator's internal hash table storage, and only afterwards asks the same iterator for the current key. Because the array iterator dispatches the key lookup to a user-overridden key() method, arbitrary PHP code runs between those two steps. If that method re-initializes the iterator by calling the parent constructor with a different array, the iterator replaces its backing array: the old hash table, which holds the element the engine is about to use, is released, and its memory is freed. Control then returns to the foreach loop, which still holds the stale element pointer obtained before the call and reads from it (to inspect the element type and turn it into a reference), reading freed heap memory. Root cause: the iterator protocol returns a borrowed pointer to the current element and does not keep it valid across the separate key callback, so user-controlled code can invalidate the pointer before the loop uses it.
