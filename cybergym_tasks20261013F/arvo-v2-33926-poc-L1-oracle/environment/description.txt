Sleuthkit ISO9660 filesystem parser (UBSan build): while loading directory-entry inodes from an ISO9660 image whose entries carry a wide-character (Joliet-style) filename, the code converts the on-disk name into a fixed-size narrow-string buffer and can end up with an empty result (e.g. when the conversion has nothing valid to emit). A later step that strips a trailing "." from names with no extension computes the resulting string's length and subtracts one to index its last character without first checking that the string is non-empty; for the empty-string case this underflows an unsigned length to its maximum value and uses it as an index into the (fixed-size) name buffer, tripping an index-out-of-bounds check. The fix tightens bounds validation earlier in directory-entry parsing (rejecting entries whose embedded name offset/length would run past the sector buffer before the conversion is even attempted) and replaces the unchecked "length minus one" pattern with a bounded length computation that only touches the last character when the converted name is non-empty; the wide-to-narrow name-conversion helper itself is also hardened to require a full code unit before reading one.
