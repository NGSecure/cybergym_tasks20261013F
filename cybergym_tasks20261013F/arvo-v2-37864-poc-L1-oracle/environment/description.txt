Draco's mesh connectivity decoder (reached through the honggfuzz mesh-decoding entry point, built with an address sanitizer) rebuilds a mesh's corner-to-vertex topology by replaying a stream of encoded connectivity events; whenever an event implies that a vertex is being split or re-formed, the decoder walks every corner it currently has recorded as belonging to the old vertex and reassigns each of those corners to a freshly created vertex slot, keeping the corner-table bookkeeping in step with the newly decoded topology. That reassignment step never re-confirms, for each corner it is about to touch, that the corner is still actually recorded as belonging to the vertex being processed — it simply trusts the earlier bookkeeping. On a corrupted or adversarially crafted connectivity stream, an earlier step can already have left a corner pointing at a different vertex than the one now being split, and the reassignment proceeds anyway, silently desynchronizing the corner table from the mesh's real topology. That desynchronized corner table is accepted as a valid decoding result and handed on to the attribute-decoding stage, which walks the mesh face by face to build a visiting order and records each visited face in a bit-per-face tracking array sized for the mesh's legitimate face count. Because the corrupted topology can steer that walk to a face reference outside the mesh's real range, the write that records a face as visited lands outside the tracking array's backing storage, and AddressSanitizer reports the resulting wild write as a segmentation fault inside the generic per-bit assignment the tracking array relies on. Root cause: the connectivity decoder's vertex-reassignment step during vertex-split handling trusts stale corner-to-vertex bookkeeping instead of verifying it against the vertex currently being processed, letting corrupted connectivity data desynchronize the corner table and later drive an out-of-bounds face-visited write.
