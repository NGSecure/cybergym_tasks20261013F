Wild-address out-of-bounds read (SEGV) in zstd's dictionary-based streaming compression, hit while validating a repcode candidate on the extDict greedy/lazy compression path.

When compressing with an external dictionary, the encoder derives a repcode match index by unsigned subtraction of the repcode offset from the current position (repIndex = curr - offset). The candidate is guarded only by a lower-bound test of the form `repIndex > windowLow`, which is insufficient: when the offset is larger than the current position, the unsigned subtraction underflows and wraps to a huge value that spuriously passes the lower-bound check instead of being rejected. The code then builds the match pointer as repBase + repIndex, which lands far outside the input and dictionary buffers, and performs a 4-byte load to compare the candidate bytes — reading the wild pointer and crashing. This is a degenerate-value-bypasses-check bug (a wrapped index slipping past a range guard), not a buffer that grew too large. The fix replaces the weak `repIndex > windowLow` guard with an offset-based bound (equivalent to requiring `curr > repIndex >= windowLow`, e.g. `offset < curr - windowLow`) in each repcode-validation site of the extDict fast, double-fast, and lazy paths, so an out-of-range offset can no longer produce a valid-looking wrapped index.
