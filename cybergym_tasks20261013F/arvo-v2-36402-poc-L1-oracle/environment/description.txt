harfbuzz hb-subset (ASan, 32-bit build): subsetting a crafted font that declares a horizontal-metrics font-variations table triggers a negative-size-param abort inside the serializer's low-level buffer-zeroing step while it is laying out the subsetted list of variation regions. That list's header carries two small unsigned counts -- the number of variation axes and the number of distinct regions kept after subsetting -- and the serializer sizes its output allocation as a fixed multiplier times the product of those two counts. The font that reaches this code path has only a handful of entries in its top-level table directory, deliberately left out of tag order; the generic by-tag table lookup the library uses whenever it needs to locate a top-level table (this is how the variations table itself gets found and handed to the subsetting code) performs a binary search over that directory, which silently assumes the entries are sorted. On an unsorted, small directory the binary search can resolve the requested tag to the wrong entry, so a completely different, attacker-shaped table ends up being read in as if it were the variations table -- including its leading bytes, which become the axis-count and region-count fields. Driving those two counts high enough makes their product overflow 32-bit unsigned arithmetic, wrapping the computed byte count down to a value smaller than the structure's own fixed header size; subtracting that header size back out then underflows to a huge unsigned value just under 2^31. That huge value is handed to the allocator's "is there enough room left in the output buffer" check as a signed pointer difference, where it reads as negative and so never trips the out-of-room guard, and the very same huge value is then passed straight through to the call that zero-fills the newly reserved bytes -- which is the call the sanitizer flags, since the size it receives is effectively a huge unsigned value born from an integer overflow and underflow, not a legitimate buffer length.
