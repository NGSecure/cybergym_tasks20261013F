HarfBuzz's font subsetter, exercised through the library's font-subsetting fuzz target (ASan build), is rebuilding a reduced copy of a font's CPAL (color palette) table and reaches that table's optional trailing extension record, which carries per-palette flag bits plus optional name-ID label lists for the palette entries and for the individual colors they reference. The color-label list is optional in the on-disk format: a font that defines no color labels signals this by leaving that list's offset field at the format's "not present" sentinel value (zero) rather than omitting the field outright. The subsetting code built a list view over that label data unconditionally, sized by the palette's separately-declared color-entry count, and then walked the view to copy across remapped label entries, all without first checking whether the offset actually indicated the list was present. Table data here is accessed by pointer directly into the loaded font's own raw byte buffer rather than through a bounds-validated copy, so when the input font supplies the sentinel "absent" value for that offset, resolving it still yields some location at/near the very end of that buffer, and the list view built from it is nonetheless treated as if it held that many real two-byte label entries there; walking the view for a palette with one or more color entries then reads past the tail of the font's own byte buffer, surfacing as a small (2-byte) heap out-of-bounds read sitting exactly at the buffer's boundary. The underlying defect is a missing presence check on an optional offset field: the degenerate "absent" encoding for that field was never distinguished from a genuine offset, so code written only for the "list present" case ran unconditionally and read label data that does not exist there, rather than any error in computing the color count itself.
