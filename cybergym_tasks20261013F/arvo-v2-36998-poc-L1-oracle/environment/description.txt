RDKit's molfile-to-mol streaming fuzz target (AFL, ASan build) raises a heap-use-after-free with the same three-frame crash signature as a related, previously-fixed wildcard-atom defect in RDKit's CXSMILES/CXSMARTS atom-label cleanup pass -- but this one survives that earlier fix and comes from a different, lower-level defect that the same cleanup pass happens to expose.

While parsing a Marvin-generated SMARTS expression embedded as an atom-property line inside a V2000 molfile's properties block, the cleanup pass recognizes a textual atom label (one of several generic query-class markers, for example one meaning "any metal atom, including a hydrogen-substituted variant") and swaps the labeled atom out for a corresponding, more direct query atom. This swap is performed by one shared low-level primitive used by every label-driven branch of the pass, not just the wildcard-only branch. That primitive already takes care to redirect one kind of secondary, pointer-based bookkeeping that refers to atoms by raw pointer (an internal lookup table keyed by atom marker) so that table is not left dangling once the original atom object is destroyed -- but it does not perform the same redirection for a second, independent kind of pointer-based bookkeeping: enhanced-stereochemistry grouping records (the kind that say "these specific atoms form a linked OR/AND stereo alternative"), which also hold atoms by raw pointer.

When the atom being swapped out happens to also be a member of one such stereo grouping on the same small, SMARTS-parsed query molecule, that grouping record is left holding a pointer to the just-destroyed atom after the swap completes. As with the related wildcard-atom defect, this particular query molecule is the kind of private sub-molecule that gets reused inside a recursive/nested substructure query; a different, unrelated field elsewhere in the same crafted molfile (a bracketed atom-list entry) later needs its own independent copy of a matching sub-molecule of this kind and triggers a deep copy of it. Deep-copying a molecule includes rebuilding its stereo-grouping records from the original's, which means reading, for every atom referenced by every such record, that atom's internal position index -- and for the dangling pointer left behind by the earlier swap, that index read lands in already-freed heap memory, producing the heap-use-after-free.

The fix adds the missing redirection to the shared swap primitive: after destroying the original atom, it now also walks the stereo-grouping bookkeeping (in addition to the marker-lookup table it already walked) and rewrites any pointer that referred to the original atom so it refers to the atom's replacement instead.
