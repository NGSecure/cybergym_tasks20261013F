A HEVC video decoder embedded in an image-format plugin (reached through HEIF image decoding) has an out-of-bounds array index when parsing the video parameter syntax of a sequence parameter set. The hypothetical reference decoder section reads a per-sub-layer "number of coded picture buffer specifications minus one" value as an unbounded Exp-Golomb code taken straight from the bitstream, then loops from 0 up to and including that value, storing bit-rate and buffer-size values into fixed arrays that hold only 32 entries per sub-layer. A value of 32 or more makes the loop index run past the end of those arrays (UBSan reports index 32 out of bounds for a 32x2 array). The value is never range-checked, and the caller also ignores the error status of this parsing step, so malformed streams keep being processed.
