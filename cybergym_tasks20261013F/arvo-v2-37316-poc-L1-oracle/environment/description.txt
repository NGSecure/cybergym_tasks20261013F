Spice's usbredir USB-redirection parser library, exercised through its libFuzzer harness under MemorySanitizer: before driving the library's normal byte-stream packet reassembly with the bulk of the fuzz input, the harness first seeds the freshly created parser object's internal bookkeeping (its queue of not-yet-flushed outgoing write buffers, among other fields) from a second, independently fuzzer-controlled chunk of bytes via the library's own serialize/restore machinery. That restore path takes the restored queue's buffer-count field at face value and, for each entry, links a newly allocated node straight into the live outgoing-buffer list before it has actually confirmed that the buffer content described for that entry is real and non-empty -- so a degenerate entry that claims to exist but carries zero bytes of payload can be accepted into the parser's live state exactly as though it were an ordinary, non-empty buffer, something the rest of the library's bookkeeping never expects to encounter. Once the parser carries that degenerate entry, the harness goes on to feed it genuine incoming packet bytes through the library's ordinary read path, which allocates a fresh heap buffer sized to the new packet's declared payload length and is only meant to treat that buffer as fully populated once every byte of it has actually arrived from the input stream; with the restore path having left the parser's internal progress accounting out of sync with reality, the "fully populated" condition for this new packet's buffer is reached before the whole buffer has genuinely been written, so when the library's own per-packet-type consistency checks go on to inspect that buffer, they read straight through the portion nothing ever wrote -- a use of heap memory `malloc()` allocated but never initialized, not an out-of-bounds access. The defect is in the restore path's failure to validate that a described outgoing buffer actually has content before splicing it into live state, not in the packet-type checking code that happens to be the one caught reading the resulting garbage.
