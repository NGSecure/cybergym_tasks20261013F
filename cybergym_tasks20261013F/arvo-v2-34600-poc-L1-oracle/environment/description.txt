One-line summary: gpac's AV1 OBU parser registers a per-call "end of stream" callback on the shared bitstream reader, handing it a raw pointer into a bookkeeping structure that only lives on the stack of the function currently probing an AV1 codec-configuration box; once that probing function returns, a completely unrelated later read on the very same bitstream can still hit end-of-file and fire the stale callback, which then writes a flag field into stack memory that no longer belongs to that structure (AddressSanitizer stack-use-after-return, 4-byte write).

Crash mechanism:
gpac parses an MP4/ISOBMFF file box by box using one long-lived bitstream reader shared across the whole parse. The input here carries a malformed AV1 codec-configuration box: the run log shows it decoding to far fewer bytes than the format requires ("read only 5 bytes (expected 14)") and leaving "9 extra bytes" unconsumed, and the embedded AV1 unit itself fails early ("computed OBU size -1 ... Skipping", "could not parse AV1 OBU ... Leaving parsing").

To determine how large the embedded AV1 sequence-header data is, a size-probing helper allocates a small "AV1 decoding state" structure as a plain local variable on its own stack frame, then repeatedly invokes the general-purpose OBU-unit parsing routine, passing that structure through as opaque state. That OBU routine, in order to notice a read that runs off the end of the available bytes mid-unit, installs an end-of-stream notification callback on the bitstream object itself, wiring it up with a bare pointer back into the caller's stack-resident state structure. The callback is meant to fire synchronously, within the same parsing call, whenever the reader underruns.

Because this particular OBU is malformed, the probing loop bails out early (matching the "Skipping" / "Leaving parsing" log lines) without ever detaching the callback it had installed on the shared bitstream object. Execution then returns out of the size-probing helper — its stack frame, and the state structure living in it, cease to exist — and box parsing simply continues on the same underlying bitstream, deeper into the rest of the file. Later, while reading an ordinary 4-byte length field for a subsequent, unrelated box, that read also runs past the end of the buffer. Because the shared bitstream object still carries the leftover callback registration from the earlier AV1 probe, the low-level byte-read path invokes it — writing into what the callback still believes is a live state structure, but whose owning stack frame returned several call levels ago and has since been reused by deeper frames in the call chain. That write lands on reclaimed stack memory, which AddressSanitizer flags as a stack-use-after-return.

Root cause, in general terms: a callback is registered on a long-lived, shared object (the bitstream reader) by handing it a raw pointer into a *caller's* stack-local structure, with no mechanism ensuring the registration is cleared once that caller's frame returns. Any later end-of-file condition on the same shared object — even one triggered from a totally unrelated part of the parse, well after the original caller is gone — dereferences a now-dangling stack address.

Fix verification:
The patch removes this whole callback-into-caller's-stack pattern for tracking bitstream overrun/end-of-stream conditions. Instead of registering an external callback that reaches back into a caller-owned structure, the bitstream reader now tracks its own overrun state internally, as a field on the bitstream object itself: the low-level read routines set that internal flag in place whenever a read would run past the end of the buffer, and callers query/reset it through two small accessor calls rather than being notified asynchronously via a stored pointer. The AV1-specific boolean that used to live in the caller's state structure (the thing the old callback wrote into) is removed from that structure's definition entirely, and every place that used to rely on it is switched to read the bitstream's own internal flag instead. Because the overrun indicator now has the same lifetime as the bitstream object rather than pointing into whatever stack frame happened to be active when it was registered, there is no window left in which a later, unrelated end-of-file event can write into memory whose owning frame has already returned. This removes the specific mechanism the crash trace shows firing (a stale end-of-stream notification into a structure that outlived its own stack frame) rather than just patching around one triggering input.

fix_commit_plausible: yes. The patch deletes the exact notification function shown at the top of the crash trace and stops the AV1 OBU-parsing routine from ever registering it on the bitstream, replacing the entire caller-supplied-pointer callback mechanism with a self-contained overflow flag stored inside the bitstream object. That is a direct, root-cause fix for a stack-use-after-return caused by a shared object outliving a callback registration into a caller's stack frame — it does not merely add a bounds check around one code path, it eliminates the dangling-pointer registration pattern itself, and the same replacement (bitstream-internal overflow flag) is then threaded through the other bitstream-consuming call sites touched by the same commit so none of them can reintroduce the same class of bug via the old external-callback API.
