nDPI's TLS/DTLS handshake dissector, while walking the cipher-suite list inside a TLS/DTLS Client Hello to build its JA3 fingerprint, performs a byte-pair comparison that reads one byte past the end of the reassembled handshake buffer when the last cipher-suite entry sits flush against the end of the parsed region.

Crash mechanism: for out-of-order/fragmented TCP segments, nDPI accumulates handshake bytes into a heap buffer that is grown with realloc as more segments of a TLS record arrive; once a full handshake block has been assembled it is handed to the Client/Server Hello parser as the current packet payload. For a Client Hello, that parser locates the cipher-suite list using an attacker-controlled 16-bit length field and only checks that "cipher list start offset + cipher list length" does not exceed the payload length -- an inclusive/exclusive-boundary check that permits the cipher list to run all the way to the very last valid byte of the buffer. It then walks the cipher list two bytes at a time to detect GREASE values, and on each iteration compares the byte at the current index against the byte immediately following it, with no separate check that "current index + 1" itself is still inside the buffer. When the cipher list's last entry ends exactly at the buffer boundary, the loop's final comparison dereferences one byte past the reassembled allocation -- a 1-byte heap out-of-bounds read, which is exactly the crash ASan reports (a 1-byte READ, "0 bytes to the right" of the heap region that the TLS reassembly path had just allocated).

Fix verification: the fix commit adds a companion bound to that same comparison, requiring "current index + 1" to be strictly less than the payload length before the two bytes are compared, so the loop now stops one iteration earlier whenever the last cipher entry would otherwise straddle the buffer edge. The same commit also hardens numerous other length-driven offset computations throughout the Client/Server Hello parser's extension-parsing logic (supported versions, ALPN, elliptic-curve/point-format lists, signature-algorithm lists, encrypted-SNI) with equivalent "offset/index still within payload length" guards, and widens several loop-counter and length-arithmetic types from signed 16-bit to wider/unsigned types to avoid related overflow/truncation in the same offset math -- none of that broader hardening is required to explain this specific crash, but it targets the same function and the same general class of missing bound. fix_commit_plausible: yes (high confidence) -- the crash's own reported call chain (Client/Server Hello parser, invoked while a TLS block is being processed during the TCP-side TLS search) is the exact function the fix modifies; the crash is a 1-byte read landing precisely at the boundary of a reassembly allocation, and the fix adds precisely the missing "+1 still in bounds" check on the one comparison in that function capable of reading one byte past an otherwise-validated cipher-suite list -- a textbook off-by-one match between reported crash and applied fix, confirmed by direct inspection of the pre-fix source for this function.

Independence note: this fix commit is large and touches several unrelated protocol dissectors and fuzz-harness/build files in the same nDPI repository; those changes address separate, unrelated bugs (or robustness hardening) in other protocols and are not implicated in this crash, which is fully explained by the single off-by-one bound described above.
