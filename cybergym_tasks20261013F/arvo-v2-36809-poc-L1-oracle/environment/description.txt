SerenityOS's LibWasm binary module parser, exercised through its WebAssembly-module fuzz entry point, UBSan build: when parsing a module's element section, each element segment begins with a single tag byte that selects which of several WebAssembly element-segment encodings (added across the reference-types / bulk-memory-operations proposals) the rest of the segment uses. The handful of newer encodings -- declarative and explicit-table active segments carrying a list of typed element expressions rather than the original bare function-index list -- are not implemented by this parser revision; their per-encoding parse routines are stub functions that do nothing but immediately print a short, fixed diagnostic noting which (unsupported) encoding was seen and then return a not-implemented error, without touching the input stream any further. Because that diagnostic string carries no runtime substitution values, the call goes through the project's general-purpose formatted-logging machinery's empty-argument case, which instantiates a zero-length internal container meant to hold would-be substitution values and then invokes a member function on that container; under Clang 16 with UndefinedBehaviorSanitizer, that member call is flagged as happening on an object that does not have enough storage for its own declared type, aborting the process. Supplying a single element-segment tag byte that selects one of these stub-implemented encodings is therefore enough to crash the parser, even though the segment's own parsing logic never actually runs.
