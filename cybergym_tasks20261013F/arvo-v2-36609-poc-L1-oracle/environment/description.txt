RDKit's molfile-to-mol streaming fuzz target (AFL, ASan build) raises a heap-use-after-free while parsing a Marvin-generated SMARTS expression that is embedded as an atom-property line inside a V2000 molfile's properties block. That embedded SMARTS text is parsed into its own small, self-contained query molecule, and once the grammar finishes building it, a cleanup pass walks every atom of that just-built molecule looking for RDKit/Marvin-specific textual atom labels (markers standing for generic query classes such as "any atom", "any heteroatom", "any halogen", and similar). For each label it recognizes, the pass swaps the labeled atom out for a freshly constructed query atom that encodes the same meaning directly, discarding the original. One branch of this pass is reserved for a plain wildcard atom that carries none of those textual labels but is still recognized as a bare "any atom" purely from its atomic number and symbol; that branch performs the exact same swap-and-discard unconditionally, without first checking whether the wildcard atom already carries a non-trivial query of its own.

On a crafted input, this particular wildcard atom's pre-existing query can itself wrap a private sub-molecule used for a nested/recursive substructure-matching pattern (the construct used when a SMARTS term means "an atom that itself matches this other, separately parsed pattern"). Swapping the wildcard atom out wholesale tears down that private sub-molecule along with everything it owns. A different, unrelated field elsewhere in the same crafted molfile's properties block -- a bracketed atom-list entry -- later needs its own independent copy of a matching recursive sub-molecule of this kind and triggers a deep copy of it. That deep copy walks the sub-molecule's atoms one by one, reading each atom's internal position index to rebuild the copy; one of the atoms it reaches is the one that was torn down by the earlier, overly eager swap, so the index read lands in memory that has already been freed -- the heap-use-after-free ASan reports, 52 bytes inside an 80-byte freed allocation, size-4 read.

The fix adds the missing precondition to that one wildcard-only branch: before performing the swap, it now checks whether the atom already carries a query, and skips the swap entirely when it does, leaving an atom with meaningful pre-existing query content untouched instead of unconditionally discarding it.
